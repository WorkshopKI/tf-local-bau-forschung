# Skill-Eval-GUI (dev)

In-App-Panel zur Evaluation eines Gutachten-Abschnitts (A–G) gegen 1–25 **fiktive** VB-Fixtures — die Browser-Schwester der Node-CLI ([src/core/services/skill-eval/cli.ts](../../src/core/services/skill-eval/cli.ts)). Verortung: Komponente [SkillEvalPanel.tsx](../../src/plugins/skill-verwaltung-kuration/SkillEvalPanel.tsx) als dev-only **Eval-Tab** in der Skill-Verwaltung (gegated `isDevFixturesEnabled()`; die OpenRouter-Judge-Option zusätzlich `isOpenRouterEnabled()`); Orchestrierung [eval-batch.ts](../../src/core/services/skill-eval/eval-batch.ts) (`runEvalBatch`).

- **Reuse, kein Fork**: `runOneSection` / `runJudge` / `aggregate` / `resolveSkill` sowie die Relevanz-Map-Helfer (`computeRelevanzMap` / `assembleVbRelevant`, [relevanz-map.ts](../../src/plugins/antraege/gutachten/relevanz-map.ts)) werden **unverändert** wiederverwendet — so bleiben In-App-Zahlen byte-vergleichbar mit der CLI (gleicher Judge-Prompt, gleiche 1–5-Skala, gleiches Aggregat, gleiche Relevanz-Auszüge). Generierung über den aktiven Bridge-Transport (intern, gpt-oss, **sequenziell** — Streamlit = ein postMessage-Fenster).
- **Kontext-Achse (A/B der Relevanz-Map)**: Umschalter `voll · relevant · beide`. Im `relevant`-Arm rechnet `runEvalBatch` die Map **einmal pro Fixture** über den internen Generator-Transport (antragsweit über alle A–G-Abschnitte, `EVAL_VB_BUDGET`) und ersetzt den VB im Prompt durch den wortgetreuen Auszug. Spiegelt die CLI-Sequenz (`vbBrauchtRelevanzMap` → `computeRelevanzMap` → `assembleVbRelevant`, `cli.ts:227–268`). **Ehrlichkeits-Pflicht**: pro Fixture wird ausgewiesen, ob die Map angewandt wurde oder der Schwellen-Check / ein leerer Auszug sie zum No-op machte (`relevanzInfos`, Panel-Zeile „Map angewandt: n/m" + Kontextgröße voll→relevant); ein A/B ohne echte Reduktion (0/m) wird als solches markiert. Dev-Eval-**Schwellen-Override** (`mapSchwelle`, Default `RELEVANZ_MAP_MIN_CHARS` = 24 000) erlaubt, kleinere Fixtures echt durch die Map zu fahren — **nie in Produktion**, `RELEVANZ_MAP_MIN_CHARS` wird nicht global gesenkt.
- **Judge (optional, Default aus)**: „Judge einschließen"-Schalter (verdoppelt die Bridge-Laufzeit; die deterministischen Checks sind das harte Gate). Judge-Transport wird **injiziert** — Default **intern-agentisch (Qwen)** über `makeAgentischerJudgeTransport(bridge.getTransportForAssistent())`: frischer Chat + `ziel:'agentisch'` + Thinking-Strip (`extractThinking`) je Submit, hält `runJudge`/`parseJudgeResult` unangetastet. Alternativ **OpenRouter** (`new DirectLLMTransport(...)`) aus der dev-eval-eigenen IDB-Config `dev-eval-judge`, nur hinter `isOpenRouterEnabled()`. Generator bleibt immer gpt-oss (die zu messende Produktionsrealität); Qwen ist ausschließlich Judge. `judgeModellId` wird getaggt (Qwen-Urteile nicht mit Sonnet-Läufen vergleichbar). Ein unparsebares Urteil → Zeilen-Fehler-Tag, **kein** Batch-Abbruch.
- **DSGVO-Guard**: Fixtures kommen ausschließlich aus dem gebündelten, gebrandeten Asset ([fixtures/bundle.ts](../../src/core/services/skill-eval/fixtures/bundle.ts) → `loadEvalFixtures`/`isFromEvalBundle`); `runEvalBatch` asserted die Provenienz **vor** jedem Lauf, der OpenRouter-Judge zusätzlich auf dem **Original-Array** (slice/map verlieren das Brand-Symbol) vor dem Transport-Bau. Der `?raw`-Import liegt nur im Literal-Guard → der ~2-MB-Fixture-String fällt aus dem prod-Bundle (erzwungen per Convention-Test `eval-gui-fictional-only`).
- **Export**: JSONL-Download (`skill-eval-<abschnitt>-<kontext>.jsonl`) — Result- + Judge-Zeilen CLI-feldkompatibel (`kontext`-Tag; Judge-Zeilen zusätzlich `judgeModellId`-gestempelt).
- **Abgrenzung**: [SkillTestlaufPanel](../../src/plugins/skill-verwaltung-kuration/SkillTestlauf.tsx) testet gegen **echte** Anträge (`listAllAntraegeListView`, `findVorhabensbeschreibung`, `doc:*`), **ohne** Judge. Die Eval-GUI darf diesen Real-Daten-Pfad nicht anfassen.
